## 1ca7efb — module interface
**08-06-2026** · `modules/vault/src/modules/vault/`

The screens, built to `MOCKUP-vault-v3-8-options-08-02-2026.html`.

- **Lock screen** — the first thing the module asks, before any data read. A failed lock read shows
  the same shell with a retry that refetches without a restart; it never routes to setup.
- **Ledger** — the stored-secrets table. Rows show metadata; a value appears only after *Reveal*,
  which is a logged read. *Copy* takes the same route, because the clipboard is a value leaving the
  vault. A hidden row drops the value from component state.
- **Entry form** — company, full name, username, website, notes, backup codes, security questions,
  with a live strength meter and a generate button. Editing never pre-fills the existing password:
  showing it would be an unlogged reveal.
- **Generator** — length, four character classes, three exclusion rules; every change regenerates
  and persists the preference to the vault's own settings.
- **Health** — score cards and a worst-first table with plain-language reasons.
- **Access log** — every read, change and refusal.
- **Vault settings** — lock section, master-password change, the seed Load/Purge card, storage
  facts, and Import/Export marked not-built in orange.

Tab strip follows the house standard verbatim. Module tokens are `--vault-*` on `.vault-shell`; the
three-class rule `.view.shown.vault-shell` is present, which the compiler cannot check.

## 7ad53c8 — engine
**08-06-2026** · `modules/vault/electron/core/services/vault/`

Schema, services, lock gate, seed, generator, health and IPC. Proven by a 16-check in-memory
harness (`npm run` command in `modules/vault/README.md`).

- **Schema** — five tables. `vault_secrets` gains presentation columns (full name, username, url,
  notes, favourite, folder) and stays credential-free; `vault_secret_versions` gains `extras` for
  backup codes and security answers, versioned with the password as one atomic unit;
  `vault_settings` and `vault_folders` are new. The access-log action vocabulary was widened to 33
  values per Jason's ruling, because SQLite cannot alter a CHECK.
- **Lock** — `[master-password-placeholder]`, seeded with Jason's email by his ruling, stored as a
  scrypt verifier. Gates the interface and IPC; does **not** derive the encryption key.
- **Seed** — 46 fake credentials from the same source as the workbook, written through the real
  services. Purge is exact and complete, including the seeded audit rows.
- **Generator** — CSPRNG, every ticked class guaranteed, Fisher-Yates shuffle, entropy estimate
  that penalises the human habits (trailing years, word runs, repeated blocks).
- **Health** — runs main-side; only verdicts cross the bridge.

**Fixed during the build, caught by the harness:** a failed unlock was only recorded if the IPC
layer remembered to log it. The audit now lives inside `lock.unlock` itself, so no route can skip it.

## 46a4b22 — seed dataset
**08-06-2026** · `modules/vault/seed/`

`VAULT-SEED-DATA.xlsx` — 46 entries, three letter pages (A-I / J-R / S-Z), columns Company · Full
name · Username / ID · URL / Website · Password · Other · Backup codes · Security questions.
Passwords are deliberately poor with engineered reuse, so the health surface has honest work.
Generated by a zero-dependency script that also emits `seed-data.ts`, so the sheet and the in-app
loader cannot drift.
