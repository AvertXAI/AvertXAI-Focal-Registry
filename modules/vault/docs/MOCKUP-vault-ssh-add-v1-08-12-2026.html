What this changes, and what it does not

The service already does all of this. store.ts accepts a publicKey on create and a passphrase in extras; sshArt derives the fingerprint and randomart; the Infrastructure pane filters on kind === "ssh_key" and renders both. The only missing pieces are in the renderer: ssh_key is absent from the editor's kind list, the two fields it needs are not drawn, and the pane has no button to open the editor. This is wiring, not new capability.

Two fields appear, and some disappear. A key has no website and no password strength, so the URL row and the generator collapse for this kind. A generator meter under a passphrase you did not generate is noise, and offering to invent a passphrase for a key that already exists on disk would be actively wrong.

The private key is out of scope, permanently. Storing it would create a second place it can leak from and save nobody a step — ssh-agent already holds it. If that is ever reconsidered it is a canon decision, not a form field.
