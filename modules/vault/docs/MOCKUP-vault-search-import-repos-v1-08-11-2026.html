Filters are chips, multi-select, and each carries its live count so an empty result is explained before you hit it. Dropping every chip searches everything. The active filters also ride inside the input as removable scopes, so what you are searching is never off-screen.
One thing to confirm. The dimmed “Hidden by your filters” group is deliberate — it shows that matches exist outside the current scope rather than silently returning three results when there are nine. Say if you would rather it just showed nothing.

And one rule I have assumed: search never looks inside a password value. It matches labels, usernames, URLs, note text, server names and repo names. Matching on the secret itself would mean decrypting all 46 entries on every keystroke, and would let anyone at an unlocked screen confirm a password by typing guesses into a search box.

Everything fetched is written to MindMerge's own database as a snapshot, so it is searchable alongside your notes and stays readable offline — which is the property that makes it worth storing rather than just opening a browser. A Save to Vault Repos action on this screen is the bridge if you later want a deploy key attached to it.
One implementation note, because it decides how much work this is. Two ways to read a repo: the GitHub API (api.github.com) returns the README and the file tree as clean JSON in two calls — no parsing, no breakage when the site is redesigned, but 60 requests/hour unauthenticated and GitHub-only. Scraping the HTML page works on any forge but breaks whenever the markup changes.

My lean is the API, with the raw README.md pulled from raw.githubusercontent.com and rendered through the Markdoc renderer we just built — so the README looks identical to a Secured Note, no second renderer. GitLab and Gitea have near-identical APIs if you want them later.

On shields.io — I would not fetch them, and I think that is the “something better” you were after. A shields.io badge is an SVG served from img.shields.io, so five badges on nine repos is 45 image requests to a third party every time the page opens, each one telling that party which repositories you track — the exact leak the MindMerge split exists to contain. They also render at fixed colours that ignore your three themes, and they show as broken images offline.

Every badge in this mockup is drawn in HTML and CSS from data already fetched — same shape, same colour conventions, about 20 lines of CSS, no network, no third party, theme-aware. The one thing lost is exotic third-party badges (Codecov, a CI provider); if you want one of those specifically it is a per-badge decision, not a blanket one.
