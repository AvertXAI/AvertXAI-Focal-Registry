Nine roles, not two hundred. A VS Code theme colours a whole IDE — the gutter, the minimap, the breadcrumbs, git decorations. A markdown code block has code in it and nothing else, so the importer reads the scopes that matter (comment, string, keyword, constant.numeric, entity.name.function, variable, entity.name.type, punctuation) and ignores the rest. Italic on comments is carried across, because SynthWave sets it and losing it changes the feel.

Decisions in here, and the one open question

Nothing third-party ships. SynthWave '84 is MIT (Robb Owen, 2019) so bundling it would be legal with the notice — but importing from your own machine is better anyway: it costs no licence bookkeeping, it works for any theme you install later, and it is the thing you actually asked for. The built-ins (Focal Light, Focal Dark) are ours.

The tokeniser is hand-written, roughly sixty lines — comment, string, number, keyword, function call, type, punctuation — over JavaScript, TypeScript, JSON, shell, SQL, Python, YAML. No Prism, no highlight.js, no new dependency in a tree being kept lean on purpose. The ceiling is real and worth stating: it is regex-based, so a pathological string full of quote characters can mis-colour a line, and an unlisted language renders plain. Neither loses you any text — colour is the only thing at stake.

Open question. The Milkdown editor pane and the Markdoc preview pane render code separately. This themes the PREVIEW. Do you want the editor's fences painted the same way? It is the same palette but a different mechanism — a ProseMirror decoration rather than a render — so it is worth knowing whether you want it before I build one of them.
