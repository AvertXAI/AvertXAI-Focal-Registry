Why monograms and not brand logos

Coloured monogram tiles are generated from the entry's own name — no third-party brand artwork ships in the app. A licensed icon pack or a favicon fetch would give real logos, and both carry their own licence and offline questions, so the monogram is the floor that always works.

The RoboForm shape — recognise by colour, not by reading. Best of the three at speed once there are thirty entries; weakest at showing history and the access log.

What happens when you save

The value is written to the encrypted vault file as version 1 and never leaves it again except through a read you can see in the access log. Changing it later appends version 2 — version 1 is kept, not overwritten.

The full entry the password manager needs. Four fields are orange because the Phase 1 schema has no column for them — this is the exact list a schema expansion would have to add.
These settings live inside the Vault only

Nothing here is reachable from the application's own Settings page. A vault that can be reconfigured from outside itself gives an attacker a lever — auto-lock, export and the master password are changed in here or not at all.

A plain export leaves the vault

Import, export, lock and storage all live inside the Vault. The application's Settings page carries no vault controls at all.
⚠ Standing design flag — no master password exists today

The vault file unlocks automatically at boot from a key held by the operating system's credential store. No prompt, no auto-lock timer, no locked state — so anyone with the machine unlocked and the app open can reveal every secret. Defensible for a taxpayer identifier the app itself needs; not defensible for a password manager. A master password, an auto-lock timer and a locked state are the first thing the full build adds.
